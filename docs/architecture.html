What runs when you ./bin/hiveshare-server with Postgres + Redis from docker-compose.yml / Podman.

2 · Server boot sequence

Exact order in cmd/server/main.go.

  1. Install JSON slog as default logger
  2. store.NewPool(ctx) — parse DSN / env, set pool limits, AfterConnect SET ivfflat.probes = 10, ping
  3. redis.ParseURL(REDIS_URL) default redis://localhost:6379, ping
  4. Construct stores: UserStore, HiveshareStore, MemoryStore, MetricsStore
  5. embed.New() from EMBED_PROVIDER (openai | ollama | NoOp)
  6. realtime.NewHub(rdb)
  7. ViewCounter.StartFlusher(ctx, 60s)
  8. embed.NewWorker(..., workers=2, queue=64).Start(ctx, 2)
  9. Background purgeUsageEvents — DELETE rows older than 90 days, then every 24h
  10. api.NewRouter(...) → http.Server{ReadTimeout:15s, WriteTimeout:60s}
  11. Listen LISTEN_ADDR (default :8080); SIGINT/SIGTERM → 10s graceful shutdown

4 · Request flows (super specific)

POST …/memory (add)

  1. AuthMiddleware → UserStore.GetByAPIKey (SHA-256 match)
  2. IsMember; reject if viewer
  3. MemoryStore.Create(..., embedding=nil) INSERT
  4. worker.Enqueue({EntryID, Content}) non-blocking; drop if queue full
  5. RecordEvent(event_type=add)
  6. Hub.Publish → Redis PUBLISH hiveshare:<id>:events
  7. HTTP 201 with entry (no vector yet)
  8. Worker: Embed → UPDATE embedding

POST …/memory/search

  1. Auth + membership (viewer OK)
  2. Sync embedder.Embed(query) (search path only)
  3. If vector OK: ORDER BY embedding <=> $2 HNSW, embedding IS NOT NULL
  4. Else: to_tsvector @@ plainto_tsquery + ts_rank
  5. Returns full content + score
  6. usage_events search row

GET …/stream (SSE)

  1. Auth + membership
  2. Hub.ServeSSE: register local chan []byte (buf 32)
  3. If first local client for hiveshare → start Redis sub goroutine
  4. Write event: connected
  5. Loop: read local chan → event: <type> + JSON payload
  6. On disconnect: unregister; if last client → cancel/close Redis sub

GET …/memory/{id} (views)

  1. Load row from Postgres (full content)
  2. ViewCounter.Increment → Redis INCR
  3. Response views = db_views + pending_redis
  4. Every 60s flusher: SCAN hiveshare:views:*, GETDEL, UPDATE views = views + Δ
  5. Also records usage_events type view

6 · Data model & Redis keys

PostgreSQL tables

  • users — id, email, name, api_key (hash), created_at
  • hiveshares — spaces; owner_id, settings JSONB
  • hiveshare_members — PK (hiveshare_id, user_id), role CHECK
  • invitations — token, status, expires_at (+7d default)
  • memory_entries — content, summary, vector(1536), tags[], views, reuses
  • usage_events — add/view/search/invite_* · 90-day TTL job

Redis keyspace

  • hiveshare:<uuid>:events — Pub/Sub channel (JSON StreamEvent)
  • hiveshare:views:<entry_uuid> — integer delta until flush

StreamEvent types today: connected (SSE only), memory_added, memory_updated.
